- **Order:** R0a and R0b first. Then R1 to R4 in parallel: their files don't
  overlap. R2 and R3 report the `docs/enforcement.md` rows they need, which
  land in one docs pull request after the wave (decision 98).

  which share one set of approved hashes, so splitting them would make each
  phase conflict in `agents-template.test.ts`. #475 closes with R3.
- **R1 and R2 are delicate:** each brief gets ChatGPT Sol 6.1's adversarial
  review and a re-check before it builds.
- **This repo's own `AGENTS.md` and guides** take the new text at the pin
  bump, not in R1. Its `AGENTS.md` is at 194 of 200 lines, so the pin bump
  moves this repo's own text to docs if the block grows past the limit.
- **Release:** after R1 to R4 and the enforcement rows, follow
  [`docs/releasing.md`](../releasing.md) (R0b): prepare 0.2.2, tag and publish on the
  maintainer's yes, freeze the baseline, then the pin bump, each its own pull
  request. The release notes list the changed guides.

## Who does what

- **Orchestrator:** the session on the primary checkout. It writes every
  brief, reviews every line, owns the shared files, and does every push and
  merge.
- **Builders:** one per phase, each in its own harness-made worktree,
  committing only, with models the maintainer confirms before each starts.
- **ChatGPT Sol 6.1:** adversarially reviews the R1 and R2 briefs, and reviews
  every code pull request alongside the orchestrator.
