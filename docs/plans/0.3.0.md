# Plan: temple-bar 0.3.0

Theme: **new repositories from zero.** The milestone's issues are placed by the
maintainer:
[milestone 0.3.0](https://github.com/londontypescript/temple-bar/milestone/8).

This plan replaces the partial one that held only the Windows CI work. That
work is done: W2 and #463's G0 to G2 merged and shipped in 0.2.1, and W1 was
dropped. The record is on #454 and #463.

## Decisions

Every open question across the milestone was settled in one decide-first pass
on 2026-10-30, after an adversarial review of the background by ChatGPT Sol
6.1, which also reviewed this plan. Before a phase's brief is written, its
issues' **Decided** sections are brought up to date (the maintainer sees each
text first), so no issue body contradicts the plan. The decisions that shape
the phases:

- **The README gets one stop-gap pass,** closing #461 and #341: two
  independent drafts, combined, and approved by the maintainer as a rendered
  page before the pull request. The proper rewrite stays with #388 and #433,
  in a later milestone.
- **#360, #365 and #362 close without a phase,** as scope decisions.
  grand-union builds and render-tests its Vite app in CI on every pull request
  (its `render.yml`), so `docs/setup.md` links it as the worked example;
  gate-enforced delivery stays #56. #362 is superseded by decision 86, #323
  and #479.
- **Setup sets the repository's squash defaults** (title and body from the
  pull request): one more entry in decision 40's list. Decision 86 said setup
  doesn't, so both ADR 0004 and ADR 0016 are amended, and the required pr-title check also fails a description missing the branch's trailers. #497, phase S.
- **A new gate check refuses a lint script that lets warnings pass,** for
  ESLint, oxlint and Biome only, under the command grammar approved in #496.
  Phase L.
- **New repositories are public, under an owner the user names and agrees,**
  not only londontypescript. This revises the 2026-10-10 scope and gets an
  ADR in phase H. README's "any TypeScript project" line stays.
- **The judge lets catalog bumps through without the maintainer** under a
  strict text grammar approved in a revised ADR 0015 (phase E0) before any
  code; new packages still need the maintainer in 0.3.0. A guarded script
  template in `temple-bar.config.json` is filed as a later issue before
  #457 closes.
- **Cleanup after merge** is an explicit `leftovers --remove`, which removes
  only worktrees their owning session has marked released. #333, #336 and
  #337 join that phase.
- **CodeQL setup never waits:** it reports "not finished" honestly and a
  rerun finishes. It sets only languages present on `main`, never repairs an
  existing entry, and says finished only once the gate's own threshold test
  passes against the live rules.
- **A probe comes first** (phase P) on throwaway public repositories, for
  what GitHub does with CodeQL default setup and with rulesets on a
  user-owned repository later transferred. Creating, transferring and
  deleting each repository wait for the maintainer's yes at the time.

`One concern:` reasons:

- A: the README's description of setup, in one place.
- H: the one call that creates and first pushes a new repository.
- Q: CodeQL's path from "on" to "required and covering the repository".
- I: deleting what a merge leaves behind, safely.

Order and parallel work. No two phases running at once own the same file;
"their tests" means each phase's own test files, and a shared fixture belongs
to the phase that lands first.

- **Wave 1:** A, B, C, E0 and P (each repository on the maintainer's yes).
- **After C:** D, since C rewrites tests D touches. D is admin-merged before
  wave 2's pull requests queue CI.
- **Wave 2, after D:** F1, F2, I and L; H once P is done; E once E0 is
  approved.
- **After F1, F2 and H:** S, which touches `offerProtection`, its question and
  the command tests H and F2 use.
- **Last:** Q, after S and P.
- **Release:** B's step runs before the tag. AGENTS.md is at 200 of 200
  lines; H, I and L may add template lines, so the room is measured on the
  final block. Then the baseline freeze and the pin bump, each its own pull
  request.

**Shared text has one owner.** After A, the orchestrator owns `README.md`,
`docs/setup.md`, `docs/enforcement.md`, the companion guide text
(`init/companion-docs.ts`, `init/companion-guides.ts`), the AGENTS.md
template (`init/agents-template.ts`) and earlier-block hash registration, the
ADR index, and the shared config files. Builders put the lines they need in
their handoff. ADR numbers are reserved before wave 1 starts. Enforcement
rows from one wave land after it.

## Who does what

- **Orchestrator:** this session, on the primary checkout. It writes every
  brief, reviews every line, owns the shared files, and does every push and
  merge. It runs P itself and combines A's two drafts.
- **Builders:** one per phase, each in its own harness-made worktree,
  committing only. Proposed, for the maintainer to confirm before each
  starts: Fable 5.1 at high effort for E0 (critical); Opus 5.5 at extra-high
  effort for D, E, H, I and Q (delicate); Opus 5.5 at high effort for A's
  first draft, as agreed, and for L and S (involved); Opus 5.5 at medium
  effort for C, F1 and F2 (routine); Haiku 5.5 for B (mechanical).
- **ChatGPT Sol 6.1:** writes A's second draft independently; reviews E0's
  design adversarially; reviews each delicate phase's brief before it builds
  and re-checks the revised brief; reviews every code pull request alongside
  the orchestrator. Effort high throughout.
