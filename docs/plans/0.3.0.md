# Plan: temple-bar 0.3.0

Theme: **new repositories from zero.** The milestone's issues are placed by the
maintainer:
[milestone 0.3.0](https://github.com/londontypescript/temple-bar/milestone/8).

**This plan is partial on purpose.** The maintainer asked for the Windows CI
speed-up first, so the plan starts with
[#454](https://github.com/londontypescript/temple-bar/issues/454)'s two
phases and nothing else. The rest of the milestone is planned later, after its
decide-first pass, in a pull request that extends this file. Nothing below
claims a file another 0.3.0 issue names.

## Decisions

#454's own plan was approved by the maintainer on 2026-10-25, after an
adversarial review by ChatGPT Sol 6.1 and Claude Fable 5.1 and a re-check by
ChatGPT Sol 6.1. Its record, measurements included, is on the issue.

- **Phase W1 caches git's index only within an explicit batch of writes,**
  not once per run (safe today only through call order) and not by watching
  the index file's stat (inode and timestamp edge cases, and a timestamp guard
  would remove the gain).
- **W1 records a new ADR,** taking the next number: it changes the "nothing
  cached" design of the fix that made setup never write through a symlink.
  - [#300](https://github.com/londontypescript/temple-bar/issues/300)
- **W2 uses neither `fast-import` nor a long-lived `cat-file --batch`:** the
  first breaks the tests that delete a loose object, and the second needs an
  asynchronous fake for a small gain.

## Who does what

- **Orchestrator:** this session, on the primary checkout. It writes every
  brief, reviews every line, owns the shared files, and does every push and
  merge.
- **Builders:** one per phase, each in its own harness-made worktree,
  committing only. Proposed, for the maintainer to confirm before each
  starts: Opus 5.5 at extra-high effort for W1 (delicate), Opus 5.5 at
  medium effort for W2 (routine).
- **ChatGPT Sol 6.1:** adversarially reviews W1's brief before it builds,
  then re-checks the revised brief (effort medium). It reviews both code pull
  requests alongside the orchestrator (effort high).
