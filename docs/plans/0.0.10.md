## Contracts selected

- Mandatory Markdown integrity: actual local links/images including supported HTML references, and undefined explicit full/collapsed reference labels. No universal style lint, no default existence assertion for inline code citations, no advisory citation feature or opt-in configuration in this release.
- Project Markdown style configuration is left to project-owned scripts. It neither configures nor disables the mandatory integrity set. Do not honor generic markdownlint-disable directives for that mandatory set: framework directives must not silently suppress it. Intentional literal examples belong in code or escaped text.
- Defer section-anchor validation, empty-link and table-cell rules, duplicate-label machinery and MDX support. Preserve existing local target semantics unless a demonstrated incompatibility needs a decision; inspect submodule and docs-site cases rather than promise universally supported paths.
- Historical upgrades use authentic published output identities, preserve edits and unknown newer output, never downgrade shared hooks, and report ambiguity/conflicts. Keep current shim bytes when possible. Do not create a new forward-compatibility runtime protocol or loosen the gate to trust a marker. Explicitly document immutable older-gate limits.
- Scaffold compatibility is not full gate success. Expected missing scripts are exact per-scaffold fixture data; every other failure is a finding. The strict checker lands only after compatibility repairs.
- SvelteKit diagnosis precedes a fix. No plugin disabling, blanket entries/ignores, phantom files or speculative version bump.

## Verification and boundaries

Every new check has meaningful negative evidence from its own diagnostic: remove the fix, repack/install, observe intended failure, restore. Full suite always runs; no diff-selected testing or weakened checks. Source never becomes this repository's tooling. Report 'passes locally; CI not yet seen' until CI is green. Check-changing PRs require maintainer admin merge under the repository's rules.

Preserve local subtask state; no routine intermediate GitHub comments. One final concise issue comment at completed phase/task. Stop on sandbox/hook refusal; no global installs or bypass. Before broad edits explain whether one change spans files or duplication needs removal.
